# AGENTS.md

This file provides guidance to Codex when working with code in this repository.

## Running the app

From the repo root:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt   # includes PyQt6
python3 main.py
```

The venv is **required**, not a preference: Homebrew's Python is externally managed, so `pip3 install -r requirements.txt` aborts with `externally-managed-environment` (PEP 668), and `/opt/homebrew/bin/python3.14` has no PyQt6 of its own. `ffmpeg`/`ffprobe` must be on Homebrew (`/opt/homebrew/bin`). yt-dlp runs as the venv's `yt_dlp` *package*, never a system binary, and must stay current or downloads 403 — follow `.claude/skills/check-ytdlp/SKILL.md` to check, diagnose or upgrade it.

Note `ps` shows the Homebrew `Python.app` binary even when running from the venv (macOS venvs exec the base framework stub for GUI support) — check `sys.prefix` to confirm which environment is live.

To launch, screenshot or smoke-test the app without a display, use the `run-autonotes` skill (`.agents/skills/run-autonotes/`) rather than driving Qt by hand.

Two setup paths deliberately differ from the above and should not be "fixed" to match it: `build.sh` targets `/opt/homebrew/bin/python3.14` and installs PyInstaller with `--break-system-packages`, so a PyInstaller build expects the dependencies importable by *that* interpreter, not the venv (untested against a venv). `build.sh` refuses to build when that interpreter doesn't meet `requirements.txt` (`scripts/check_deps.py`; Homebrew-owned packages such as `certifi` need `brew upgrade`, not pip). CI (`.github/workflows/build.yml`) installs the exact pins in `requirements.lock` (regenerate with `scripts/write_lock.py`, see its header) into the unmanaged interpreter `actions/setup-python` provides, then runs `ruff check` (`ruff.toml`) and the tests under coverage with a floor (`.coveragerc`); `monthly-rebuild.yml` deliberately installs from `requirements.txt` instead, to catch extractor rot. Actions are pinned to commit SHAs, and only the tag-triggered `release` job has `contents: write`.

## Architecture

AutoNotes is a PyQt6 desktop app that converts a YouTube URL or local video file into a structured DOCX with AI-generated notes and screenshots.

### Pipeline (7 stages)

`pipeline/worker.py` — `ProcessingWorker(QThread)` orchestrates everything. It runs off the main thread and emits signals (`stage_changed`, `stage_progress`, `log_message`, `completed`, `error`) that the UI connects to. The pipeline runs in a `tempfile.mkdtemp` directory that is cleaned up on exit.

Stages in order:
1. **Download** (`pipeline/downloader.py`) — wraps `yt-dlp` for YouTube URLs; local files are used directly. Teams/SharePoint downloads (`pipeline/teams_downloader.py`) use browser cookies (`--cookies-from-browser chrome`, then `edge`) to authenticate. `ffmpeg` is assumed at `/opt/homebrew/bin`. When no VTT/SRT lands, `pipeline/sharepoint_transcript.py` fetches the Teams transcript from SharePoint's Stream API — yt-dlp's SharePoint extractor never populates `subtitles`, so `--write-sub` is a no-op for `stream.aspx` URLs. It scrapes the page's `g_fileInfo` blob for `.spItemUrl` (site path / drive / item — note site collections may be `/teams/`, not just `/sites/` or `/personal/`) plus a `hasTranscripts` flag, calls `items/{id}?$expand=media/transcripts` for a pre-signed `temporaryDownloadUrl`, then reads it with `format=json`. Entries already carry `speakerDisplayName`, so a transcribed recording skips Whisper *and* diarization. Reuses the same cookies as the download — no Azure app registration needed. This is the only Teams transcript source; the Graph client deliberately does not fetch transcripts (so it never needs `OnlineMeetingTranscript.Read.All`) and supplies only attendees, the AI recap and the title. The recap comes from Microsoft 365 Copilot's meeting insights API (`/copilot/users/{id}/onlineMeetings/{id}/aiInsights`; the old `/meetingInfo` path never existed), needs a Copilot licence and `OnlineMeetingAiInsight.Read.All`, and is requested as a separate consent after sign-in (`get_recap_token`) so a refusal never costs the attendee list; a refusal is remembered so later runs don't prompt again. Any failure returns `None` and the pipeline transcribes normally.
2. **Audio extraction** (`pipeline/transcriber.py`) — `ffmpeg` extracts a 16 kHz mono WAV.
3. **Transcription** (`pipeline/transcriber.py`) — `faster-whisper` runs on CPU with `int8` compute; returns `[{start, end, text}]`.
4. **Diarization** (`pipeline/diarizer.py`) — optional pyannote speaker ID keyed on HuggingFace token. Silently falls back to `"Speaker"` if token is absent or pyannote fails. Adds `speaker` field to each segment.
5. **Frame extraction** (`pipeline/frame_extractor.py`) — ffmpeg extracts one frame every 5 s in a single decode pass (capped at `EXTRACT_WIDTH`, never upscaled), OpenCV detects a presentation-screen quadrilateral in each frame and crops to it when found (with a score bonus, since a shown screen is inherently relevant); near-upright quads (`_MAX_AXIS_TILT_DEG`) get a pixel-exact bounding-box crop — only genuinely skewed (filmed) screens are perspective-warped, so screencast content is never rotated by imprecise corner detection, near-duplicate frames are collapsed via a 256×144 grayscale diff sensitive enough to catch a single bullet appearing (one best frame per slide/scene), flat composited letterbox bands are trimmed per frame (`pipeline/letterbox.py`), each survivor is scored for screen-content likeness — slides, demos, terminals, browsers, dashboards — via edge density + gradient rectilinearity + color simplicity + uniformity, plus a bonus near transcript visual-cue phrases ("as you can see", "let me show", …). The dedup signature is computed on the central content region only (`_SIG_REGION`), so Teams webcam galleries/captions at the frame edges don't defeat dedup, and a duration-scaled budget (`_frame_budget`: one per 30 s, clamped to 8–60) is picked greedily by score with a ≥25 s minimum gap (`MIN_GAP_SECONDS`) so one busy stretch can't crowd out the rest of the video; result sorted by timestamp. An empty result (audio-only file, unreadable video, ffmpeg failure) is logged with the reason rather than returned silently. Debug copies of each run's selections land in `~/Library/Logs/AutoNotes/`.
6. **Note generation** (`pipeline/note_generator.py`) — first checks the API key and model with a free `models.retrieve` call before the download even starts (`check_api_key`, called from the worker's pre-flight), then sends transcript text + up to `MAX_SCREENSHOTS` JPEG screenshots (base64) to `claude-sonnet-5` (override with the `AUTONOTES_MODEL` env var) and asks for structured JSON (title, chapters, key points, screenshot references). Chunked (two-call) mode triggers on transcript size only (`_TOKEN_THRESHOLD`, transcript tokens — images excluded so chunking stays rare). `screenshot_idx` values are coerced to int and validated against the provided frame set (invalid ones dropped with a log line), raw model responses are saved to `~/Library/Logs/AutoNotes/last_claude_*.json`, and the reply is normalised into the exact shape the writer reads (`_normalize_notes`: missing titles, string key points, null speakers, control characters, a sentence before the JSON). If nothing usable remains, `_fallback_notes` returns the full transcript as paragraphs and sets `notes["degraded"]`, which the worker surfaces as a warning and the document states at the top — never a silent stub under a green success. `_transport_errors()` retries network drops from both `httpx` (anthropic 0.x) and `httpx2` (1.x+). Claude also returns a per-screenshot `content_box` (fractional crop enclosing only the shared display content — excluding webcam tiles, browser chrome, docks, letterbox bars) which is clamped/validated (`_MIN_BOX_AREA`) into `notes["screenshot_boxes"]`; the docx writer crops each embed to its box at full resolution, falling back to the uncropped frame on any invalid box, and Claude is instructed not to reference webcam-gallery-only frames at all.
7. **DOCX output** (`output/docx_writer.py`) — `python-docx` builds the document: title, a source block (recording type, hyperlinked URL/path, and the recording summary — Teams AI recap preferred over the video/meeting description; a description is trimmed to `_DESCRIPTION_MAX_CHARS`), chapter headings with their time range (linked into the video at that moment for YouTube), speaker bylines, bullet points with inline `**bold**` formatting, and embedded screenshots at 5.5 in width with alt text. Every string passes through `clean_text` (XML-illegal characters crash python-docx). Saved to the configured output directory (default: `~/Desktop`).

### UI (`ui/main_window.py`)

Split-panel layout: left = inputs (URL/file, API key, HuggingFace token, Whisper model size, collapsible Microsoft Teams options, output dir) + action bar; right = stage indicator list (per-stage facts, elapsed time and a live ETA from `stage_eta`), overall progress bar weighted by typical stage length (`_STAGE_WEIGHTS`), a one-line outcome that also carries worker `warning`s, a log pane with Copy Log / Show Log File, and "Open Notes" / "Show in Finder" on completion. Inputs are locked while a run is in progress (`_running`, not `QThread.isRunning()`, which can still be true while `finished` is handled). Mac conventions: File/Run/Help menus with shortcuts, Return / ⌘↩ to start, Esc / ⌘. to cancel, drag-and-drop of a recording or link, `caffeinate` while running, and a notification plus Dock bounce when a run ends in the background. Settings save as they change. A stale-yt-dlp warning shows as a persistent banner. Help > Delete Saved Data clears the logs, saved transcript, debug frames, raw Claude replies and the Microsoft sign-in (`clear_saved_data`).

After each transcription the segments are saved to `~/Library/Logs/AutoNotes/last_transcript.json` (with video title + timestamp). A "Reuse last transcript" checkbox (enabled only when that file exists) skips audio extraction, Whisper, and diarization on the next run; the worker emits a `warning` (shown in the window, not only the log) if the saved transcript came from a different recording, and never re-saves a reused transcript — doing so used to relabel it with the new title so the warning never fired again. The checkbox unticks itself after a successful run. A transcript that came with the download (Teams VTT / SharePoint Stream API) still takes priority over the saved one.

Settings (whisper_model, output_dir, MS client ID/join URL) are persisted across launches via `QSettings("AutoNotes", "AutoNotes")`. Secrets (api_key, hf_token) are stored in the macOS Keychain via `keyring` (`ui/secure_store.py`), falling back to QSettings if keyring is unavailable — `save_secret` returns False then and the UI says so; old plaintext values are migrated on first load. The Microsoft Graph token cache (refresh tokens) is also kept in the Keychain (`graph_client._save_cache_text`), migrating the legacy `~/.autonotes_graph_tokens.json`. Everything under `~/Library/Logs/AutoNotes/` is owner-only (`_util.private_dir` / `write_private`) and `autonotes.log` rotates at 2 MB.

Cancellation is cooperative: the worker raises `PipelineCancelled` (`pipeline/_util.py`) at check points threaded through each stage via `cancel_check` callbacks (pyannote via its `hook`). Every yt-dlp/ffmpeg child goes through `_util.run_streaming` / `run_capture`, which poll the cancel check even while the child prints nothing, kill the child on the way out, and track it so Cancel and app quit can kill it at once (`kill_active_processes`). The UI never calls `QThread.terminate()`. Closing the window mid-run asks first; if the run can't stop within 10 s the window hides and the app quits when the worker finishes, so its own cleanup removes the temp folder. `sweep_stale_temp_dirs()` at launch removes `autonotes_*` temp folders older than 6 h left by a crash.

## Key constants / hardcoded paths

| Symbol | Location | Value |
|---|---|---|
| `FFMPEG` / `FFPROBE` | `_paths.py` | bundled copy in the frozen app, else `/opt/homebrew/bin/ffmpeg` |
| `_STAGE_WEIGHTS` | `ui/main_window.py` | share of a run each stage typically takes, for the overall progress bar |
| `_LOG_MAX_BYTES` / `_STALE_TEMP_SECONDS` | `worker.py` | `2 MB` log rotation / `6 h` before a leftover temp folder is swept |
| `YTDLP_CMD` | `_paths.ytdlp_command()` | `[sys.executable, "--yt-dlp"]` re-exec running the importable `yt_dlp` package, in dev and frozen alike (dispatch at the top of `main.py`); a system binary only if `main.py` is missing |
| `MODEL` | `note_generator.py` | `"claude-sonnet-5"` (env override: `AUTONOTES_MODEL`) |
| `MAX_FRAMES` / `MIN_FRAMES` | `frame_extractor.py` | `60` / `8` — budget is `duration / TARGET_SECONDS_PER_FRAME` (30 s) clamped between them, so short videos get 1 frame/30s and long ones degrade toward 1/min+ |
| `MAX_SCREENSHOTS` | `note_generator.py` | `60` (sent to Claude; chunked mode splits 30 per call) |
| `INTERVAL_SECONDS` | `frame_extractor.py` | `5` (frame sampling interval) |
| `MIN_GAP_SECONDS` | `frame_extractor.py` | `25` (min spacing between selected frames) |
| `EXTRACT_WIDTH` / `API_MAX_WIDTH` | `frame_extractor.py` | `1920` / `1000` (extraction cap, never upscales; full res kept for DOCX / downscaled copy sent to Claude) |
